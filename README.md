# Tutorly — рабочее пространство репетитора

Tutorly — веб-приложение для репетитора. В продукте только одна роль: **репетитор**. Ученики — карточки в личной базе репетитора; у учеников нет аккаунтов, авторизации и личных кабинетов.

## Что умеет эта версия

- Регистрация репетитора и вход по email/паролю.
- Хранение паролей в виде стойких хешей; JWT-сессия.
- Изоляция учеников, заданий, занятий и домашних работ по владельцу аккаунта.
- Карточки учеников: создание, редактирование, удаление, контакты и заметки.
- Библиотека заданий: создание, редактирование, удаление.
- Календарь занятий: создание и удаление занятий.
- Домашние работы: выбор ученика и заданий, сроки, статусы, оценка.
- Выгрузка домашней работы в PDF.
- Аналитика на основе данных текущего аккаунта.
- Бесплатный лимит — 3 ученика на аккаунт.
- При регистрации создаётся небольшая стартовая библиотека математических заданий.

## Стек

- Frontend: React 18 + Vite + Recharts + Lucide.
- Backend: FastAPI + SQLAlchemy + PostgreSQL + JWT.
- PDF: ReportLab.
- Развёртывание: Render (статический сайт + API) и Neon PostgreSQL.

## Переменные окружения

Backend:
- `DATABASE_URL` — строка подключения PostgreSQL (Neon). Для локального запуска можно SQLite.
- `SECRET_KEY` — случайный секрет для подписи JWT. На Render генерируйте отдельный секрет.
- `CORS_ORIGINS` — разрешённые origin фронтенда через запятую. На старте допустимо `*` (credentials не используются); для закреплённого домена укажите точный адрес фронтенда.

Frontend:
- `VITE_API_URL` — полный URL API, например `https://tutorly-api.onrender.com`.

## Публикация бесплатно на Render + Neon

1. Создайте бесплатную базу PostgreSQL в [Neon](https://console.neon.tech/). Скопируйте pooled connection string с SSL. Если строка начинается с `postgresql://`, приложение автоматически переключит драйвер на psycopg 3.
2. В Render выберите **New → Blueprint** и подключите GitHub-репозиторий `tutorly`. Render прочитает `render.yaml`.
3. При настройке Blueprint задайте `DATABASE_URL` — строку Neon — и `VITE_API_URL` — URL API-сервиса Render (для имени `tutorly-api` обычно `https://tutorly-api.onrender.com`).
4. Дождитесь публикации `tutorly-api` и `tutorly-web`. Если Render назначил другой URL API, обновите `VITE_API_URL` у Static Site и запустите новый Deploy.
5. В настройках API оставьте `CORS_ORIGINS=*` на первом запуске. После публикации можно заменить на точный URL сайта, например `https://tutorly-web.onrender.com`.
6. Откройте URL `tutorly-web`, зарегистрируйте репетитора и проверьте создание ученика, занятия, задания и домашней работы.

Бесплатные сервисы могут иметь ограничения и менять условия. Бесплатный Render Web Service засыпает после простоя; первое обращение после сна может занять некоторое время. Бесплатная база Neon также имеет квоты и может приостанавливать вычисления. Это не SLA и не гарантия непрерывной доступности.

## Локальный запуск (необязателен)

Нужны Docker Desktop и Docker Compose. Из корня проекта:

```bash
docker compose up --build
```

Frontend: `http://localhost:5173`  
API docs: `http://localhost:8000/docs`

## Текущие ограничения и безопасность

- Это первая интегрированная версия, а не сертифицированный production-сервис. Перед использованием реальных данных нужно провести полный тест в облаке, включить резервное копирование и проверить правила хранения персональных данных.
- Оплата Pro не подключена; тариф Free действует с ограничением до 3 учеников. Не переключайте тарифы вручную в базе.
- Для production обязательно используйте собственный `SECRET_KEY`, не публикуйте `.env`, пароли и строки подключения.
- В текущем backend схема БД создаётся через `create_all`; для дальнейших изменений схемы рекомендуется добавить Alembic migrations.
- Бесплатный Render backend засыпает при бездействии. Neon Free имеет ограничения по вычислительным часам и объёму.

## Структура
